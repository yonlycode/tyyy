<p>On m'a demandé l'autre jour : « Pourquoi tu héberges pas ton site sur Vercel ? C'est gratuit, c'est simple. »</p>
<p>J'ai souri. Pas un sourire amical. Un sourire de quelqu'un qui vient de calculer le coût réel du « gratuit » sur cinq ans.</p>
<p>Parce que le « gratuit » de Vercel, de Netlify, de Supabase, de Cloudflare Pages, c'est comme le « gratuit » du supermarché : le produit, c'est vous. Ou pire, c'est votre dépendance.</p>
<p>Mon portfolio ne coûte <strong>rien</strong>. Pas 0,01€. Pas 3€. Zéro. Et je suis fier de ça.</p>
<h2>Le piège du « free tier »</h2>
<p>Voici ce qui se passe quand vous hébergez sur un SaaS :</p>
<ul>
<li>Le free tier vous donne <strong>200MB de base de données</strong>. Vous avez du trafic ? Il passe à du payant.</li>
<li>Le « gratuit » inclut <strong>50GB de bandwidth</strong>. Un article qui passe sur Hacker News ? Bye bye.</li>
<li>La plateforme que vous aimez peut <strong>changer ses tarifs</strong>, fermer, ou se faire racheter par un conglomérat qui transformera votre site en portail publicitaire.</li>
<li>Votre contenu n'est <strong>pas chez vous</strong>. Il est en location. Dans un cloud. Dont vous ne contrôlez rien.</li>
</ul>
<p>C'est de la dépendance déguisée en commodité. Et on tombe dedans tous les jours, parce que c'est plus facile au début.</p>
<p><strong>Plus facile au début. Plus cher, plus fragile, plus esclave après.</strong></p>
<h2>Mon architecture : zéro entrée = meilleure défense</h2>
<p>J'ai pris un parti simple. Radical même.</p>
<p><strong>Pas de serveur. Pas de panel admin. Pas de JWT. Pas de politique de rôles. Pas de base de données.</strong></p>
<p>Juste un outil taillé pour mon besoin.</p>
<h3>GitHub Pages — statique, gratuit, pour de vrai</h3>
<p>Mon site est un export statique. Next.js avec <code>output: 'export'</code>. Rien de plus.</p>
<p>Pas de Node.js qui tourne. Pas de runtime. Pas de processus à surveiller. Des fichiers HTML qui traînent sur GitHub Pages.</p>
<p>GitHub Pages, c'est pas un « tier ». C'est pas un « plan ». C'est <strong>gratuit, sans quota, sans limitation raisonnable</strong>, pour les repos publics. C'est du HTTP. Point.</p>
<h3>Markdown — la base de données du pauvre (qui gagne)</h3>
<p>Mon contenu, c'est du Markdown brut. Avec du frontmatter. <code>gray-matter</code> le lit, <code>remark</code> le rend, <code>reading-time</code> calcule le temps de lecture.</p>
<p>C'est du texte. Du vrai. Lisible dans un terminal en 2074. Si GitHub part en vrille demain (ça n'arrivera pas, mais supposons), j'ai tout en local. Mon portfolio, c'est mon repo. Point.</p>
<h3>GitHub Actions — le CI/CD invisible et gratuit</h3>
<p>Quand je commit sur <code>main</code>, GitHub Actions détecte le changement dans <code>web/**</code>, rebuild le site, et le déploie. Automatique. Invisible. Gratuit.</p>
<p>Pas de pipeline à maintenir. Pas de serveur CI à héberger. GitHub le fait pour vous, gratuitement, parce que c'est dans leur business model de héberger du code open source.</p>
<h3>L'app desktop — le CMS qui n'est pas un SaaS</h3>
<p>On m'a demandé : « Pourquoi tu fais pas juste un Notion ? »</p>
<p>Parce que Notion, c'est du SaaS. Et du SaaS, c'est de la dépendance.</p>
<p>J'ai pas envie de taper dans Git pour écrire un article. VS Code + terminal, c'est bien pour coder, pas pour écrire du contenu. Donc j'ai construit <strong>tyyy-Admin</strong> : une app desktop native.</p>
<ul>
<li><strong>Backend</strong> : Go, via Wails. Pas de HTTP. Pas d'API key sur un disque. Le PAT GitHub reste en cache mémoire.</li>
<li><strong>Frontend</strong> : React 19 + Vite 7. Un éditeur Markdown avec aperçu live.</li>
<li><strong>Persistance</strong> : Commits GitHub sur <code>main</code>. L'app lit, écrit, commit. C'est tout.</li>
</ul>
<p>Pas de « cloud ». Pas de « synchronisation ». Juste un commit.</p>

<p>Le seul truc qui me coûte de l'argent, c'est mon électricité pour faire tourner l'app desktop. Et encore… sur un M1 Max, c'est négligeable.</p>
<h2>Pourquoi une app desktop ?</h2>
<p>Parce que j'ai pas envie de dépendre d'une plateforme pour écrire.</p>
<p>Notion, Google Docs, WordPress.com — tous ces outils sont beaux, fluides, bien pensés. Et tous ont un point commun : <strong>si le service arrête, vous avez perdu votre contenu.</strong> Ou pire, on vous le rend difficile à extraire.</p>
<p>Mon app ? Elle tourne sur <strong>ma</strong> machine. Elle fait <strong>exactement</strong> ce que je lui dis. Elle commit sur <strong>mon</strong> repo. Si elle casse, je la recode. En une soirée.</p>
<p>C'est pas sexy. C'est pas scalable. C'est pas « enterprise-ready ».</p>
<p><strong>C'est à moi.</strong></p>
<h2>GitHub est un monopole ? Oui. Et alors ?</h2>
<p>Ok, je suis le premier à dire que GitHub est un monopole. Et Microsoft derrière. C'est pas parfait.</p>
<p>Mais c'est un monopole <strong>open source</strong> avec des <strong>repos publics</strong>. Mon code est là. Mon contenu est là. Mon infrastructure, c'est du Git.</p>
<p>Si GitHub ferme demain, je peux cloner mon repo. Je peux le push sur GitLab, Bitbucket, ou un serveur Git self-hosté. Le Markdown, ça vit partout. L'HTML statique, pareil.</p>
<p><strong>La vraie dépendance, ce n'est pas GitHub. C'est le format propriétaire.</strong></p>
<p>Tant que mon contenu est en Markdown et mon site en HTML statique, je suis libre.</p>
<h2>Le nom : « le portfolio du rat »</h2>
<p>Oui, c'est volontaire. Je suis rat.</p>
<p>J'ai pas envie de payer 40 abonnements pour héberger 3 pages statiques. J'ai pas envie que mon site dépende d'une startup qui peut changer ses tarifs, fermer, ou se faire racheter.</p>
<p>Je vis dans les murs. Je grignote ce que les géants me laissent. Et je suis content.</p>
<p>Le rat, c'est celui qui survit quand tout s'effondre. Pas le héros. Pas l'entrepreneur en hoodie qui vend du « free tier » aux débutants. Le rat. Celui qui a un plan B, un C, et un D.</p>
<h2>La vraie question</h2>
<p>Voici la question qui devrait vous tenir éveillé, pas celle sur le framework JavaScript de la semaine :</p>
<p><strong>Quand est-ce que tu arrêtes de payer pour quelque chose que tu pourrais faire toi-même ?</strong></p>
<p>Pas pour prouver que tu es malin. Pour prouver que tu es libre.</p>
<p>Mon portfolio vit dans un repo Git. Mon contenu, c'est du Markdown brut. Ma « base de données », c'est <code>links.json</code>. Mon « backend », c'est un pipeline GitHub Actions.</p>
<p>Et ça me coûte <strong>zéro euro</strong>.</p>
<p>Le code est public. <a href="https://github.com/yonlycode/tyyy">github.com/yonlycode</a>. Fork. Copie. Pique. C'est open source.</p>

<ul>
<li>Pas de Vercel. Pas de Netlify. Pas de Supabase. Pas de « freemium » qui vous piège.</li>
<li><strong>GitHub Pages</strong> pour l'hébergement. Gratuit. Pour de vrai.</li>
<li><strong>Markdown</strong> pour le contenu. Lisible en 2074.</li>
<li><strong>GitHub Actions</strong> pour le déploiement. Invisible. Automatique. Gratuit.</li>
<li><strong>Une app desktop</strong> (Wails/Go/React) pour écrire. Sur ma machine. Pour moi.</li>
<li><strong>0€ d'infra.</strong> 0€ de base de données. 0€ de backend.</li>
<li>Le code est open source. Fork. Copie. Pique.</li>
