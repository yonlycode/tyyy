12:Tdc0,<h2>Mon portfolio ne coûte rien. Le tien, probablement trop cher.</h2>
<p>Pas de Vercel. Pas de Netlify. Pas de Supabase. Pas de "freemium" qui vous piège avec des quotas qui disparaissent quand vous avez du trafic.</p>
<p>Juste :</p>
<ul>
<li><strong>GitHub Pages</strong> (statique, gratuit, pour de vrai)</li>
<li><strong>Un repo</strong> avec des fichiers Markdown</li>
<li><strong>Un pipeline GitHub Actions</strong> qui rebuild à chaque commit</li>
<li><strong>Une app desktop</strong> (Wails/Go/React) qui commit à ma place</li>
</ul>
<p>C'est tout.</p>
<p>On m'a demandé : "Pourquoi tu fais pas juste un Notion ?"</p>
<p>Parce que Notion, c'est du SaaS. Et du SaaS, c'est de la dépendance déguisée en commodité.</p>
<p>Mon site vit dans un repo Git. Mon contenu, c'est du Markdown brut. Ma "base de données", c'est <code>links.json</code>. Si GitHub part en vrille demain (ça n'arrivera pas, mais supposons), j'ai tout en local. Mon portfolio, c'est mon repo. Point.</p>
<h2><strong>L'architecture :</strong></h2>
<ul>
<li><code>web/</code> → Next.js en export statique. <code>output: 'export'</code>. Zéro serveur. Zéro runtime. Des fichiers HTML qui traînent sur GitHub Pages.</li>
<li><code>admin/</code> → App desktop native. Go backend + React frontend. Pas de HTTP. Pas d'API key sur un disque. Le PAT GitHub reste en cache pour plus de facilité.</li>
<li>Contenu → Markdown + frontmatter. <code>gray-matter</code>, <code>remark</code>, <code>reading-time</code>. C'est du texte. Du vrai. Lisible dans un terminal en 2074.</li>
<li>CI/CD → GitHub Actions détecte un push sur <code>main</code>, rebuild, déployé. Automatique. Invisible. Gratuit.</li>
</ul>
<p><strong>Le budget :</strong> 0€ d'infra. 0€ de base de données. 0€ de backend.</p>
<p>J'ai même mis Google Analytics. Client-side uniquement. Pas de cookie banner RGPD. Pas de consentement à accepter. Le script charge, GA track, c'est tout. Anonymisé. Pas de tracking de merde.</p>
<h2><strong>Pourquoi une app desktop ?</strong></h2>
<p>Parce que j'ai pas envie de taper dans Git pour écrire un article. Parce que VS Code + terminal, c'est bien pour coder, pas pour écrire du contenu. L'app, c'est un CMS. Mais un CMS qui n'est pas un SaaS. Qui tourne sur ma machine. Qui commet sur mon repo. Qui fait exactement ce que je lui dis.</p>
<p>Pas de "cloud". Pas de "synchronisation". Juste un commit.</p>
<p><img src="/tyyy/images/screenshot-2026-08-19-at-22.02.36.png" alt="screenshot-2026-08-19-at-22.02.36.png"></p>
<p><strong>Nom de code : "le portfolio du rat".</strong></p>
<p>Oui, c'est volontaire. Je suis rat. J'ai pas envie de payer 40 abonnements pour héberger 3 pages statiques. J'ai pas envie que mon site dépende d'une startup qui peut changer ses tarifs, fermer, ou se faire racheter par un conglomérat qui transformera mon site en portail publicitaire.</p>
<p>GitHub est un monopole ? Oui. Mais c'est un monopole <strong>open source</strong> avec un repo public. Mon code est là. Mon contenu est là. Mon infrastructure, c'est du Git.</p>
<p>Le seul truc qui me coûte de l'argent, c'est mon électricité pour faire tourner l'app desktop. Et encore...</p>
<p>Zéro facture. Zéro dépendance. Zéro excuse.</p>
<p>Le code est public. github.com/yonlycode. Fork. Copie. Pique. C'est open source.</p>
<p>La vraie question : <em>quand est-ce que tu arrêtes de payer pour quelque chose que tu pourrais faire toi-même ?</em></p>
