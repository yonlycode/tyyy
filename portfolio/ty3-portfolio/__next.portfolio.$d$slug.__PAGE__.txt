3:T1b69,<p>Un portfolio &#x26; blog personnel — <strong>minimal et frugal en infra</strong> — édité depuis une <strong>app desktop native</strong> qui pilote le contenu du repo GitHub.</p>
<p>Le site est un <strong>export statique</strong> (Next.js) hébergé gratuitement sur <strong>GitHub Pages</strong> : aucune base de données, aucun backend, aucun serveur à payer. Le contenu vit directement dans le repo sous forme de fichiers Markdown, et chaque sauvegarde est un commit qui redéclenche automatiquement la publication.</p>
<p>La gestion du contenu se fait via <strong>tyyy-Admin</strong>, une petite app de bureau (Wails : backend Go + frontend React) qui lit/écrit les fichiers du repo via l'API GitHub et surveille les déploiements.</p>
<hr>
<h2>🧠 L'idée en bref</h2>
<ul>
<li><strong>Zero frais d'infra</strong> : le site est un export statique servi par GitHub Pages. Rien à héberger, rien à maintenir.</li>
<li><strong>Git comme seule source de vérité</strong> : articles, projets et liens de contact sont des fichiers Markdown/JSON dans <code>main</code>. Un commit = une publication.</li>
<li><strong>Édition depuis une app desktop</strong> : pas besoin de taper dans Git ni d'éditer le Markdown à la main — l'admin s'occupe de tout et committe pour vous.</li>
<li><strong>Un pipeline invisible</strong> : sauvegarder dans l'admin → commit sur <code>main</code> → GitHub Actions rebuild → le site est à jour.</li>
</ul>
<hr>
<h2>📦 Deux packages</h2>
<p>Le repo est un monorepo contenant deux projets indépendants :</p>
<h3>1. <code>web/</code> — le site (Next.js, statique)</h3>
<p>Le portfolio &#x26; blog public, généré en <strong>export statique</strong> (SSG) et déployé sur <strong>GitHub Pages</strong>.</p>
<p>| | |
|---|---|
| <strong>Framework</strong> | Next.js 16 (App Router, <code>output: 'export'</code>) |
| <strong>Style</strong> | Emotion (CSS-in-JS) + tokens Material Design 3 + Framer Motion |
| <strong>Contenu</strong> | Markdown local (<code>gray-matter</code>, <code>remark</code>, <code>remark-html</code>, <code>reading-time</code>) |
| <strong>Rendu</strong> | Statique au build via <code>getSortedArticles()</code> / <code>getArticleBySlug()</code> |
| <strong>Pages</strong> | Accueil, articles, portfolio, contact (linktree), privacy |
| <strong>Analytics</strong> | GA4 (script côté client) |
| <strong>Hébergement</strong> | GitHub Pages via <code>deploy.yml</code> |</p>
<h3>2. <code>admin/</code> — l'app desktop (Wails : Go + React)</h3>
<p>Un <strong>CMS de bureau</strong> autonome pour éditer le contenu du repo.</p>
<p>| | |
|---|---|
| <strong>Shell desktop</strong> | Wails v2 (backend Go, aucun serveur HTTP) |
| <strong>Backend</strong> | Go 1.26, <code>google/go-github/v60</code>, <code>adrg/frontmatter</code>, oauth2 |
| <strong>Frontend</strong> | React 19 + Vite 7 + TypeScript 5 |
| <strong>Persistance</strong> | Commits GitHub sur <code>main</code> (le PAT reste en mémoire, jamais sur disque) |
| <strong>Onboarding</strong> | S'appuie sur <code>deploy.yml</code> pour installer l'écosystème |</p>
<p>Fonctionnalités : édition de <strong>articles</strong> et <strong>projets</strong>, gestion des <strong>liens de contact</strong> (réordonnables), <strong>upload d'images</strong>, éditeur Markdown avec <strong>aperçu live</strong>, et un onglet <strong>Deployments</strong> qui suit les builds du site.</p>
<hr>
<h2>🗂️ Structure</h2>
<pre><code>tyyy/
├── Makefile            # Commandes unifiées (web + admin)
├── web/                # Le site Next.js (export statique)
│   ├── content/        # Le contenu du site (la source de vérité)
│   │   ├── articles/   # .md des articles
│   │   ├── projects/   # .md des projets
│   │   └── links.json  # liens de la page /contact
│   ├── src/            # app router, composants (Emotion), lib (md/links), theme
│   └── next.config.ts  # output: 'export', basePath '/tyyy', trailingSlash
└── admin/              # L'app desktop Wails
    ├── main.go         # embarque le SPA + bind les méthodes Go
    ├── pkg/
    │   ├── app/        # App struct — méthodes exposées (GetConfig, SaveArticle, …)
    │   └── content/    # modèles Article/Project/Links + implémentation GitHub
    └── frontend/       # SPA React + Vite + TS
</code></pre>
<p>Le site et l'admin partagent le <strong>même contrat de contenu</strong> : frontmatter <code>title</code>, <code>description</code>, <code>date</code>, <code>tags</code>, <code>published</code> pour les articles/projets, et <code>{ id, label, url, icon, enabled }</code> pour les liens.</p>
<hr>
<h2>🚀 Prise en main</h2>
<h3>Prérequis</h3>
<ul>
<li><strong>Node.js 22+ LTS</strong> (corepack) + <strong>Yarn 1.22</strong></li>
<li><strong>Go 1.26+</strong> + le <strong>Wails CLI</strong> (<code>wails doctor</code> pour les deps système) — pour l'admin seulement</li>
<li>Un <strong>GitHub PAT</strong> avec scope <code>repo</code> (lecture/écriture contenu + lecture Actions) — pour l'admin</li>
</ul>
<h3>Installation</h3>
<pre><code class="language-bash">make install          # admin-install + web-install
</code></pre>
<h3>Web</h3>
<pre><code class="language-bash">make web-dev          # dev server (http://localhost:3000)
make web-build        # build statique -> web/out
make web-start        # servir le build localement
make web-lint         # ESLint
</code></pre>
<h3>Admin</h3>
<pre><code class="language-bash">make admin-dev        # app desktop en dev (HMR, ouvre la fenêtre)
make admin-build      # build -> admin/build/bin/tyyy-admin.app
make admin-run        # ouvrir l'app compilée
</code></pre>
<hr>
<h2>🔄 Workflow d'édition</h2>
<ol>
<li>Lancer <strong>tyyy Admin</strong>, renseigner le token + repo (<code>yonlycode/tyyy</code>) + branche <code>main</code>.</li>
<li>Créer/éditer un article, un projet ou les liens de contact.</li>
<li><strong>Sauvegarder = committer</strong> sur <code>main</code> (l'app gère les conflits 409 en demandant un rechargement).</li>
<li><code>deploy.yml</code> détecte le push sur <code>web/**</code>, rebuild le site et le publie sur GitHub Pages.</li>
<li>Suivre le statut dans l'onglet <strong>Deployments</strong>.</li>
</ol>
<hr>
<h2>🤖 CI/CD (GitHub Actions)</h2>
<p>| Workflow | Déclencheur | Rôle |
|---|---|---|
| <code>deploy.yml</code> | push sur <code>main</code> (chemin <code>web/**</code>) | Build SSG + déploiement GitHub Pages |
| <code>admin-ci.yml</code> | push/PR sur <code>admin/**</code> | <code>go vet</code>, <code>gofmt</code>, build Wails (Linux) |
| <code>release.yml</code> | tag <code>v*</code> | Build + package l'app desktop (macOS/Linux/Windows) attachés à une release |</p>
