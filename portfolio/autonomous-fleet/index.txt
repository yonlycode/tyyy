<p>Les démonstrateurs d'agents IA « tout-au-prompt » (boucles ouvertes, ReAct non borné) séduisent sur les réseaux sociaux mais s'effondrent dès qu'ils rencontrent le monde réel :</p>
<ul>
<li>Boucles de réflexion infinies consommatrices de budget.</li>
<li>Hallucinations sur les arguments d'outils et corruption d'état.</li>
<li>Zéro auditabilité : impossible d'expliquer pourquoi l'agent a touché tel fichier ou posté tel truc.</li>
</ul>
<p>Notre réponse n'est pas un framework d'agents de plus. C'est une <strong>flotte d'agents aux rôles strictement bornés</strong>, chacun marié à un harness déterministe, sur une infrastructure qu'on auto-héberge de bout en bout.</p>

<p>Chaque agent est une instance <strong>Hermes Agent</strong> avec sa propre mémoire persistante, ses skills versionnées dans un repo dédié, et un contrat : l'agent délègue le code à son harness, relit, valide, et ne pousse jamais à l'aveugle.</p>
<h2>L'Infrastructure Souveraine</h2>
<p>Tout tourne sous notre contrôle, rejoints par un tailnet privé :</p>
<ul>
<li><strong>Forgejo</strong> : git, CI Actions, registry npm/OCI, wiki = base de connaissances unique de la flotte.</li>
<li><strong>Coolify</strong> : orchestration des conteneurs (les instances d'agents, les services, les bancs d'essai).</li>
<li><strong>Tailscale</strong> : le réseau. Rien n'est exposé publiquement qui ne devrait pas l'être.</li>
<li><strong>SeaweedFS</strong> : stockage objet pour les artefacts lourds et froids.</li>
<li><strong>MongoDB</strong> : persistance des produits (leads, événements, configs box).</li>
<li><strong>Inférence locale</strong> : llama.cpp sur AMD Strix Halo (mesures publiées sur ce blog) et endpoint LLM du MacBook — plus des API cloud ponctuelles quand le cloud est l'outil adapté.</li>
</ul>

<h2>Les Principes Qui Tiennent</h2>
<ul>
<li><strong>Un agent, un rôle, un harness.</strong> Bueno ne touche pas l'infra ; Migo ne rédige pas les posts LinkedIn. Les périmètres sont écrits, pas implicites.</li>
<li><strong>Le harness est borné par construction.</strong> Les tâches sont déléguées à un worker headless (dsh, agy) avec un contrat explicite : ces fichiers, pas de commit, pas de push. L'agent relit et valide avant tout merge.</li>
<li><strong>La connaissance est versionnée.</strong> Skills des agents et wiki d'infra vivent dans Forgejo, pas dans la tête d'un agent. Un agent reconstruit se reconstruit documenté.</li>
<li><strong>Le cloud est un outil, pas une fondation.</strong> Les API propriétaires passent par des points de passage identifiés et budgétés ; l'orchestration, la donnée et la mémoire restent à la maison.</li>
</ul>
<h2>État Réel Du Projet</h2>
<p>La flotte tourne au quotidien (cette page a été documentée par un de ses membres). Nous n'avons pas de « taux de succès de 98 % » à vous vendre : nous avons des agents qui font le travail, une infra qui tient, et des process qui se renforcent à chaque incident. C'est moins sexy qu'un essaim de huit agents fantômes, c'est surtout vrai.</p>
